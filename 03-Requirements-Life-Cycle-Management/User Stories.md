# User Stories (BABOK® Technique)

## What This Technique Is
User Stories describe requirements in a user-centered format:
> As a <user>, I want <goal>, so that <benefit>.

They support incremental delivery and encourage focus on user value.

## Why This Technique Exists
Traditional requirements can be heavy and slow. User stories:
- simplify communication
- support agile planning
- encourage collaboration
- keep focus on outcomes

## When to Use
- Agile delivery (primary)
- Hybrid programs with incremental delivery
- Backlog-driven work management

## How to Write Good User Stories
1. Identify the user/role
2. Define the goal (what they need)
3. State the benefit (why it matters)
4. Add acceptance criteria (testable)
5. Refine and split if too large

## Example (Banking / IT)
As an Operations Analyst, I want to view reconciliation breaks by category so that I can resolve exceptions faster.

Acceptance criteria:
- filter by break type
- export results
- show counts and aging

## Common Mistakes
- Stories without acceptance criteria
- Technical tasks written as stories (not user goals)
- Stories too large (“epics”) and not split
- Missing “so that” (no value)

## Related Techniques
- Backlog Management
- Acceptance Criteria
- Prototyping
- Prioritization

## Key Takeaway
User stories communicate value simply, but must be paired with clear acceptance criteria.
