# 10.13 Data Flow Diagrams

## 1. Purpose
Data Flow Diagrams (DFDs) are used to model how data moves through a system. They show the processes that transform data, the data stores that hold data, and the external entities that produce or consume data.

## 2. Description
DFDs provide a visual representation of the flow and transformation of data within a scope. They are excellent for illustrating the boundaries of a system and how it interfaces with the outside world. DFDs do not show control logic (like loops or decisions); they focus exclusively on the movement of data.

## 3. Key Elements (Gane-Sarson Notation)
- **Process:** An activity that transforms data. Represented by a rectangle with rounded corners.
- **Data Store:** A place where data is held for later use (e.g., a database table). Represented by an open-ended rectangle.
- **External Entity:** A person, organization, or system outside the scope that sends or receives data. Represented by a square.
- **Data Flow:** The movement of data between other elements. Represented by an arrow.

## 4. Levels of DFDs
- **Context Diagram (Level 0):** A high-level view showing the entire system as a single process with its external entities.
- **Level 1 DFD:** An explosion of the Context Diagram, breaking the main process into its major sub-processes.
- **Level 2 DFD (and lower):** Further decomposition of Level 1 processes to show more detail.

## 5. Usage
- To understand and communicate the data requirements of a system.
- To identify processes, data stores, and external dependencies.
- As a starting point for data modeling.
