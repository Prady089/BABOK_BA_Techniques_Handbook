# Root Cause Analysis (BABOK® Technique)

## 1. What This Technique Is

Root Cause Analysis (RCA) is a technique used by Business Analysts to **identify the underlying causes of problems**, rather than treating symptoms.  
It focuses on answering **why a problem occurs**, so that solutions address the real issue and prevent recurrence.

RCA is essential when problems are recurring, complex, or have high business impact.

---

## 2. Why This Technique Exists

Many organizations repeatedly fix symptoms instead of causes, leading to:
- Recurring defects
- Rework and inefficiency
- Increased operational risk

Root Cause Analysis exists to help a BA:
- Understand the true source of a problem
- Prevent repeat failures
- Improve process and system stability
- Support effective decision-making

BABOK includes RCA because **effective change depends on accurate problem definition**.

---

## 3. When to Use Root Cause Analysis

Root Cause Analysis is most effective when:
- Issues are recurring
- Problems span multiple teams or systems
- Incident impact is high
- Compliance or audit findings exist
- Process breakdowns are suspected

Common BA scenarios:
- Operational incidents
- Reporting errors
- Data quality issues
- System outages
- Regulatory breaches

---

## 4. When NOT to Use Root Cause Analysis

RCA may add limited value when:
- The problem and cause are already obvious
- The issue is isolated and non-recurring
- Immediate tactical fixes are sufficient

In such cases, **direct corrective action** may be more appropriate.

---

## 5. Common Root Cause Analysis Techniques

### 5 Whys
Repeatedly asking “why” to drill down to the root cause.

### Fishbone Diagram (Ishikawa)
Categorizes potential causes (People, Process, Technology, Data, etc.).

### Fault Tree Analysis
Maps failure paths logically to identify root causes.

### Pareto Analysis
Focuses on causes contributing to the majority of problems.

---

## 6. How to Apply Root Cause Analysis – Step by Step

### Step 1: Clearly Define the Problem
Document:
- What happened
- When and where it occurred
- Impact and frequency

### Step 2: Collect Data
Gather:
- Incident reports
- Metrics and logs
- Stakeholder inputs

### Step 3: Identify Possible Causes
Use:
- Brainstorming
- Fishbone diagrams
- Historical data

### Step 4: Analyze Causes
Apply techniques such as:
- 5 Whys
- Cause elimination
- Pattern analysis

### Step 5: Identify Root Causes
Confirm causes that:
- Directly lead to the problem
- Are within control to address

### Step 6: Recommend Corrective Actions
Propose actions that:
- Address root causes
- Prevent recurrence

### Step 7: Validate and Monitor
Confirm effectiveness and monitor outcomes.

Typical outputs include:

---

## 9. Common Mistakes by Business Analysts

- Stopping at symptoms instead of causes
- Relying on assumptions instead of data
- Blaming individuals rather than processes
- Failing to validate causes
- Not following through on corrective actions

---

## 10. Real-World Example (Banking / IT)

**Scenario:** Repeated trade reconciliation breaks

Symptoms:
- Daily manual corrections

Root Cause Analysis reveals:
- Inconsistent upstream data feeds
- Missing validation rules
- Manual workarounds masking system issues

Outcome:
- Data validation rules added
- Process controls strengthened
- Breaks reduced significantly
